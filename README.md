# 熱血！ニャンコ大運動会 ONLINE — 2人対戦・初期プロトタイプ

## 構成
- `server.py` — Python aiohttp による HTTP＋WebSocket とルーム管理
- `static/index.html` — スマホ横画面対応のロビー・対戦クライアント
- `static/assets/` — 既存の4匹のキャラクター待機絵と四角い格闘会場
- `requirements.txt` / `Procfile` — デプロイ用

## ローカル起動

```bash
pip install -r requirements.txt
python server.py
```

同じWi-Fi上の2台のスマホで、PCのLAN IPにアクセス（例: `http://192.168.1.5:8080`）。公開サイトならHTTPS/WSS対応のサーバーにデプロイすること。

## 遊び方
1. 1台目が「部屋を作る」→6桁コードを取得
2. 2台目は同じURLでコードを入力して参加
3. 別々のキャラクターを選んで、両者「準備完了！」
4. 5区間レース→格闘大会（60秒）→綱引き→総合結果
5. 各競技結果画面で2人が次へ進むと続行

### 操作
- 左パッド：移動、レースは右方向へ走る
- レース：ジャンプ／ダッシュ
- 格闘：パンチ／必殺技（ゲージ満タンで使用可能）
- 綱引き：連打／リズム

## 重要な開発段階の制限
- **この版はオンライン同期・大会進行の第1試作**。旧1人用版の全攻撃判定、全区間の障害物挙動、綱引きの太鼓ノーツ・トーナメント全演出などは未移植。
- 2人＋CPU2匹の参加、位置・HP・得点の同期、3競技と結果発表のつながりを優先。
- 綱引きは現在、プレイヤー同士の準決勝 → 勝者対CPUの決勝という暫定編成。
- プレイヤーの途中離脱からの再接続、観戦、通信遅延補正、チート対策、永続化は今後の課題。
- 部屋データはサーバープロセスのメモリ上のみ。**複数サーバー台数に増やさず、まずは単一インスタンスで稼働させる**こと。
- サーバーを公開する場合は、運用上の制限（レート制限・ログ・WSS・負荷）を追加してから大規模な宣伝を行うこと。

## ホスティング
Render/Railway等のPython Webサービスを使用。
開始コマンド：`python server.py`、必要環境変数：`PORT`（提供されるものを使用）。
静的サイトサービス（GitHub Pages等）だけではリアルタイム対戦はできない。
